Security · Incident response

Muster

Incident response playbooks, drawn, versioned and run live.

Security teams draw their playbooks as diagrams, keep every version, and run them step by step during a real incident or a tabletop exercise. The incident report writes itself from the run.

  • Visual editor for actions, decisions and escalations, validated before publishing
  • Live runs with SLA clocks and a shared timeline; exercise mode up to ×300
  • Report drafts exported to PDF or Markdown; ten NIST-mapped playbooks included

Node.js 22 · SQLite · React · Docker

Security · Network mapping

Strata

Your network, in layers.

A 3D map of an organisation’s information system: zones, VLANs, assets and flows stacked as layers, with what is exposed, what is vulnerable and who to call. Every change is reviewed before it reaches the map.

  • 3D model and 2D diagrams sharing the same positions
  • Exposure by source (Internet, other VLAN, same VLAN) and asset sheets with contacts
  • Architecture plans, flow matrices and firewall rules; Cyberwatch, GLPI, phpIPAM and Palo Alto connectors

Node.js, zero dependencies · JSON storage · Docker · systemd

What we stand for

Most of the software that runs the world is locked. We build the open alternative, and we don't ask permission to start.

Open source is no excuse for sloppy work. Code review, tests and documentation come standard on every project.

Security is part of done. Every project publishes a disclosure policy, signs its releases and fixes reported issues first.

Free as in freedom. What we build stays open, under licenses that keep it that way for everyone who comes after.

The Solid standard

Every Solid Geeks project ships with the same baseline, so you know what you get before you read a line of code.

  • [x]A license from our policy, declared in every source file with an SPDX header.
  • [x]Tests that run in CI on every pull request.
  • [x]A SECURITY.md with a private way to report vulnerabilities.
  • [x]Signed releases and a changelog people can read.
  • [x]Docs a newcomer can follow from clone to first run.
  • [x]Commits signed off under the Developer Certificate of Origin.

How we license
